## Usage

```tsx
import { AgentProvider, useAgent } from '@/components/ui/agent'

function App() {
  const agent = useAgent({ allow: (step) => step.action !== "press" || confirm(`Press ${step.label}?`) })
  return <AgentProvider agent={agent}>{/* your app */}</AgentProvider>
}

agent.snapshot()
// [{ ref: "c1", component: "input", label: "Project name", value: "Apollo", actions: ["setValue", "clear"] }, ...]

await agent.act({
  steps: [
    { ref: "Project name", action: "setValue", args: ["Atlas"] },
    { ref: "Region", action: "select", args: ["Europe"] },
  ],
})
```

Inside `AgentProvider`, the form controls and Dialog register their state and actions with the agent. An action calls the component's own state setter, not a synthetic click, so it runs through your `onValueChange` and `onOpenChange` like any other change. Anything that does not register is still reached through the accessibility tree, so the rest of the page works too. Outside a provider the components behave as before.

An agent gets a short list of labelled controls instead of the page's HTML, and names them by label instead of selector.

## What the agent sees

| Control | Read | Actions |
|---|---|---|
| Input, Textarea, OTPField | `value`, and `length` for OTPField | `setValue`, `clear` |
| NumberField | `value`, `min`, `max`, `step` | `setValue`, `increment`, `decrement` |
| Slider, CompareSlider | `value` (a number, or `[low, high]` for a range), `min`, `max`, `step` | `setValue` |
| Select | `value`, `open`, `items` when open or passed as `items` | `select`, `open`, `close` |
| Combobox | `value`, `open`, `items`, `multiple` | `select`, `search`, `open`, `close`, and `setValue` when `multiple` |
| Autocomplete | `value` (the text), `items` | `setValue`, `search` |
| RadioGroup, ToggleGroup | `value`, `items`, `multiple` | `select`, and `setValue` when `multiple` |
| CheckboxGroup | `value`, `items` | `setValue`; each checkbox in it also takes `toggle` and `setChecked` |
| Checkbox, Switch, Toggle | `checked` (`"mixed"` when indeterminate) | `toggle`, `setChecked` |
| Dialog, AlertDialog, Drawer | `open` | `open`, `close`. Presses inside an AlertDialog need approval |
| Popover, PreviewCard | `open` | `open`, `close` |
| Collapsible, Accordion item, ExpandableCard | `open` | `open`, `close` |
| Menu, ContextMenu, Menubar menu | `open` | `open`, `close`; each item takes `press`, and `setChecked` when it can be checked |
| NavigationMenu | `open` for an item with a trigger, listed as `menu` | `open`, `close`; links take `press` |
| Tabs, AnimatedTabs | `value` (the selected tab), `items` | `select` |
| Carousel | `value` (the current slide), `items` | `goTo`, by label or by number from 1 |
| Sortable | `items` in order | `move`, an item to a position from 1 |
| SwipeableRow | its content as a region; its actions as buttons | `press` on each action, `dismiss` when it has `onDismiss` |
| HoldToConfirm | needs approval by default | `press`, which completes the hold |
| Button | `open` for dialog triggers | `press` |
| Link, any `a[href]` | `value` (the href) | `press` |
| Progress, ProgressRing, any `progressbar` | `value`, `min`, `max`; no `value` while indeterminate | none |
| Meter, any `meter` | `value`, `min`, `max` | none |
| Toast | `value` (the description), `type`; its buttons as `button` | `dismiss` |

A popup with no title of its own goes by its trigger's name. Choices are matched by label, then by value. A miss lists the options. Inside a Field, a control also reports `required`, `invalid` and the Field's `errors`, and `in` names its Fieldset or Form.

A step names its control by `ref`, by label, or by kind when only one of that kind is on the page. Steps run in order and stop at the first failure; earlier steps are not undone. `act` returns each step's new value and the controls that `appeared`, such as an opened dialog.

## Agent changes

```tsx
<Select
  onValueChange={(value, details) => {
    if (isAgentChange(details)) track("agent-picked-region", value)
    if (value === "ap") details.cancel()
  }}
/>
```

`isAgentChange(details)` tells an agent's change from a person's. Calling `details.cancel()` refuses it, and the step fails with "The app refused the change."

## Controlling access

- `data-agent-hidden` removes a region from the snapshot.
- `data-agent-part` marks an element that belongs to a control registered with `useAgentControl`, so it is not listed a second time. Controls inside it are still found.
- `data-agent-secret` reports a value as `[redacted]`. Password, one-time-code and card fields are secret already.
- `data-agent-confirm="Reason"` marks a control that needs a person. Without `allow` the step fails with that reason; with it, `allow` receives the reason as `confirm`.
- `data-agent-label` names a control when its accessible name is not what an agent should use.
- `data-agent-dismiss` marks the button `dismiss` presses in a toast. Toast's close button has it.
- Content behind an open modal is out of the snapshot, as it is out of reach for a person.

## WebMCP

```tsx
useAgent({ webmcp: { allow: (step) => confirm(`Let the browser agent ${step.action} ${step.label}?`) } })
```

Registers `snapshot`, `query` and `act` with the browser's agent. It does nothing in browsers without WebMCP. Its `allow` is required and runs after the bridge's own.

For any other model SDK, `agentTools` holds the three tool definitions and `runAgentTool(agent, name, input)` runs one.
