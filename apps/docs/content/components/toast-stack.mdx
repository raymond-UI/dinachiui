## Usage

```tsx
import { ToastStack, ToastStackItem } from "@/components/ui/toast-stack"
import { ToastProvider, ToastTitle, ToastDescription, useToastManager } from "@/components/ui/toast"
```

Put the stack where Toast's viewport would have gone, inside the same provider.

```tsx
function Notifications() {
  const { toasts, close } = useToastManager()

  return (
    <ToastStack className="fixed bottom-4 right-4 w-80">
      {toasts.map((toast) => (
        <ToastStackItem key={toast.id} toast={toast}>
          <div className="min-w-0 flex-1">
            <ToastTitle className="text-sm font-medium">{toast.title}</ToastTitle>
            <ToastDescription className="text-xs text-muted-foreground">
              {toast.description}
            </ToastDescription>
          </div>
          <button type="button" onClick={() => close(toast.id)}>Dismiss</button>
        </ToastStackItem>
      ))}
    </ToastStack>
  )
}
```

Anywhere in the app, unchanged:

```tsx
const { add } = useToastManager()

add({ title: "Saved", description: "Draft synced to the server" })
```

## Depth, not height

Three notifications should cost the same screen area as one until the reader shows
interest. Collapsed, the toasts behind the front one are pushed back with a scale and a
small vertical offset, so the stack reads as depth rather than as a list that has been
cropped. Hovering or focusing it expands it into the real column.

That depth is `scale` and `y`, never height or margin. The stack has to be able to expand
and collapse while a toast is entering or leaving, and layout properties cannot be
interrupted mid-flight without jumping.

## The open positions are measured

Toasts are not all one height: a two-line body pushes the next one down. Multiplying a
constant by the index is right exactly until the first toast wraps, after which every toast
under it overlaps. Each toast reports its own height and the column is built from those.

## Timing is not its job

Nothing in the stack counts down. `timeout` on the provider, or on a single `add()`, is
what decides how long a toast lasts, and `timeout: 0` keeps one until it is dismissed by
hand. Base UI pauses those timers while the stack is hovered or focused, which is the same
signal that expands it, so there is no second clock here to keep in step.

```tsx
<ToastProvider timeout={5000}>

// A warning the reader has not seen is not a warning that has been delivered.
add({ title: "Quota at 90%", timeout: 0 })
```

## Which viewport to use

| Toast Stack | Toast's own viewport |
| --- | --- |
| Notifications that arrive in bursts, where three at once should not take a third of the screen. | A single confirmation, or messages that arrive one at a time. |
| Messages the reader may want to go back and read. | Anything with an action that must be reachable without hovering first. |

Both are viewports on the same queue, so switching is a change of one component.

## Behaviour

- **Placement and width are yours.** The toasts are absolutely positioned inside the stack
  element, so give it the corner and the size you want it to occupy. It has no height of
  its own.
- **It takes Toast's viewport props**, since it is one. Anything you would pass to
  `ToastViewport` goes here.
- **One toast past the visible depth is rendered invisibly**, so the toast moving up into
  the stack fades in rather than appearing whole.
- **A toast can be flicked away sideways**, and the flick is projected the same way a
  [swipeable row](/docs/components/swipeable-row) projects: what the gesture meant, not
  where the finger happened to stop.

## Accessibility

- **The viewport is Base UI's live region**, so toasts are announced without you doing
  anything. This is the reason to render the queue through the stack rather than to hold a
  list of your own.
- **Each toast is a labelled dialog** and can be reached with F6. `ToastTitle` and
  `ToastDescription` are what name it, so put them inside the item rather than around it.
- **Focus expands the stack**, not just hover. A keyboard reader reaching the second
  toast's button cannot be asked to hover first.
- **Reduced motion drops the drag**, so dismissing is only ever the button. Give every
  toast one.
